# Optional accounts; answers are private to their account

Accounts were added on 2026-10-23 so a Compliance Officer can keep a Firm Profile, a dashboard and a searchable archive of their own questions. Accounts are optional: without one the app works as before, and guest answers stay in a shared guest history (changed on 2026-10-28, see below). An account's answers are visible only to that account; asking for another account's answer returns "not found" rather than "forbidden", so ids reveal nothing. Accounts hold an email address, a name, the Firm Profile and the answers, which is personal data: passwords are stored only as salted scrypt hashes, sessions only as SHA-256 hashes of random tokens in an httpOnly cookie, and deleting an account deletes its answers too. There is no email verification and no password reset, because both need a mail service; that is the first thing to add before real users. Rejected for now: logins through an identity provider (Microsoft Entra ID, as large banks and insurers use), which is the likely target for a real deployment but needs a tenant to test against.

## Amended 2026-10-28

Guests no longer share one history. Every browser without a session gets a signed guest id in an httpOnly cookie (introduced for the rate limit), and a guest's answers are filed under a hash of that id: the history, a stored answer and its export are visible only from the browser that asked, and an unknown id still answers "not found". A request without any guest id, such as a plain API call, owns nothing. The reason is the one behind this ADR: a question often reveals what a Firm is working on, and on a shared or public deployment a shared guest history would have shown every guest the questions of every other. The guest answers stored before this change have no guest id and are visible to nobody. Clearing cookies starts a new, empty guest history; an Account is the way to keep one.
